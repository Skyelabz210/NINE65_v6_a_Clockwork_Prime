# Implementation Plan: `/consult` Command
**Global Context-Aware External Audit System**

## Context

The user needs a token-efficient way to get external audit reports on projects without bloating the main Claude session's context window. Currently, when working across multiple projects in `~/Projects` (NINE65/v5, NINE65/MANA, NINE65/QClassic, QMNF_System, exact_transcendentals, etc.), getting rigorous external analysis requires manually collecting context, invoking external consultants, and managing the communication loop.

**The Problem**:
- Main Claude session context window gets consumed by loading large files
- Repeatedly checking for report completion wastes tokens
- Manual orchestration of external consultants is tedious
- Different projects have different contexts that need preservation

**The Solution**:
A `/consult` slash command that:
1. Auto-discovers project context (file paths, not contents)
2. Invokes external CLI consultants (codex, qwen, gemini, or claude headless)
3. Implements intelligent wait/polling protocol
4. Delivers concise audit reports for assessment (not directive execution)
5. Works globally but remains context-aware of current project

## Critical Requirements

### 1. Token Efficiency
- **No file loading** - Provide paths only, let consultants read files
- **Polling protocol** - Structured wait times, not continuous checking
- **Notification-based** - Claude main session informed via message, not repeated tool calls

### 2. Working Directory Awareness
- Execute from **current working directory** when `/consult` invoked
- NOT from session start directory
- User responsible for knowing their location

### 3. CLI Consultants Available
- `/usr/local/bin/codex` - ChatGPT CLI (default consultant)
- `/home/acid/.npm-global/bin/qwen` - Qwen CLI (coder model)
- `/home/acid/.npm-global/bin/gemini` - Gemini CLI
- `claude` - Claude Code CLI (headless mode)
- All subscription-based, no API keys needed

### 4. Multi-Consultant Configuration (All Headless)
- **Default**: Codex only (fast, single perspective)
- **Optional**: Multiple consultants in parallel
- **All run headless/non-interactive**: No user interfaces, just read context and produce reports
- **Examples**:
  - `/consult` → Codex only (headless)
  - `/consult --all` → All 4 consultants (all headless)
  - `/consult --agents codex,qwen` → Specific combination (both headless)
  - `/consult --agents gemini` → Single alternative (headless)

### 5. Enhanced Wait Protocol (Silent)
```
Launch consultant(s) → Silent checks at 2, 3, 4, 5 min → Present prompt if not ready
```
- Check schedule: 2min, 3min, 4min, 5min (4 checks total)
- **Total wait time**: 5 minutes
- **Silent operation**: No announcements like "checking now...", only check file existence
- **On timeout (5 min elapsed)**: Don't assume failure, prompt user:
  ```
  "Wait protocol time expired. Would you like to:
   - Extend wait period (reset counter)
   - Move forward (report may still be generating)"
  ```

## Implementation Structure

### Phase 1: Slash Command Definition
**Location**: `~/.claude/commands/consult.md` (global command)

**Frontmatter**:
```yaml
---
description: Launch external consultant audit with intelligent wait protocol
---
```

**Command Logic**:
1. Parse arguments: `--all`, `--agents <list>`, optional project name override
2. Detect current project from `pwd` (must be under `~/Projects/`)
3. **Pre-consultation preparation**: Copy current plan/blueprint to jobs folder
4. Invoke Python orchestrator script
5. Display initial notification with receipt time

### Phase 2: Python Orchestrator Script
**Location**: `~/Projects/scripts/consult_orchestrator.py`

**Responsibilities**:

**Pre-Flight: Claude Copies Current Plan** (BEFORE orchestrator runs):
1. Claude identifies most current execution context:
   - Latest plan from `docs/plans/*.md` OR
   - Current blueprint from `state/blueprint.json` OR
   - Active task from `.claude/gap-analysis/latest-report.md`
2. Claude copies this to: `jobs/<project_name>/CURRENT_CONTEXT_<timestamp>.md`
3. This becomes the **primary** context document for consultants
4. Purpose: Focused, up-to-date context vs outdated READMEs or sprawling codebase

**Orchestrator Responsibilities**:
1. **Context Discovery** (Temporal Focus - CURRENT work only):
   - **PRIMARY**: `jobs/<project_name>/CURRENT_CONTEXT_<timestamp>.md` (copied by Claude)
     - This is THE source of truth - current plan/blueprint/task
     - Consultants should start and focus here
   - **SUPPORTING** (minimal, only if needed):
     - `README.md` - Project overview (if exists)
     - `CLAUDE.md` - Development guidelines (if exists)
   - **EXCLUDE** (to avoid circular analysis):
     - Historical gap-analysis reports (could be our own old findings)
     - Old execution plans (not current)
     - Previous consultant reports (avoid self-referencing)
   - Build list of **absolute file paths** (not contents)
   - **Temporal qualifier**: Consultants focus on CURRENT_CONTEXT for where we're going NOW

2. **Consultant Prompt Generation** (Agent-Agnostic, Temporal Focus):
   ```
   **SYSTEM ROLE:** You are an independent technical consultant conducting an unbiased evaluation of the system or subsystem provided to you. Your deliverable is a structured, actionable analysis report.

   **CRITICAL - TEMPORAL FOCUS:** This project has 14+ months of development history with many prior analyses. DO NOT reference historical gap analyses, old execution plans, or previous consultant reports. Focus on the CURRENT plan and provide FRESH analysis.

   **PRIMARY CONTEXT:** /home/acid/Projects/<project>/jobs/<project_name>/CURRENT_CONTEXT_<timestamp>.md
   This file contains the CURRENT execution plan, blueprint, or active task description. This is where we're going NOW. Start your analysis here and focus your recommendations on enhancing THIS specific effort.

   **WORKING DIRECTORY:** /home/acid/Projects/<project>/

   **YOUR TASK:** Review and analyze the current plan. Identify:
   - Gaps in the current approach
   - Points of enhancement or refinement
   - Opportunities for improvement
   - Potential risks or precautions
   Provide forward-looking, actionable insights aligned with where we're going NOW.

   **SUPPORTING REFERENCE FILES** (if needed for project context):
   - /home/acid/Projects/<project>/README.md (project overview)
   - /home/acid/Projects/<project>/CLAUDE.md (development guidelines)

   **ANALYSIS MANDATE:**
   Ground your evaluation in these key traits:
   1. **RIGOR** - Assess internal coherence, correctness, logical soundness. Verify assumptions and evaluate implementation fidelity relative to stated goals.
   2. **FUNCTIONALITY** - Determine whether the system performs its intended tasks reliably under expected constraints. Identify incomplete or unstable components.
   3. **SCALABILITY** - Evaluate capacity to expand in load, complexity, or modularity without degrading performance or maintainability.
   4. **CORRECTNESS** - Detect violations of design intent, logical or type errors, and inconsistent interface behaviors.
   5. **UTILITY** - Identify practical effectiveness—how well it serves its use case and whether design choices enhance or obscure purpose.

   **DELIVERABLE FORMAT:**
   Produce a structured audit report at:
   /home/acid/Projects/<project>/jobs/<project_name>/consult_<consultant>_<model>_<timestamp>.md

   **Report Header** (identifies consultant and model):
   ```markdown
   # CONSULTANT AUDIT

   **Consultant**: <Codex|Qwen|Gemini|Claude>
   **Model**: <o1-preview|qwen-coder-turbo|gemini-2.0-flash-thinking-exp|opus>
   **Timestamp**: <ISO 8601 timestamp>
   **Project**: <project_name>
   ```

   ## EXECUTIVE SUMMARY
   Key findings at a glance (2-3 sentences).

   ## SYSTEM OVERVIEW
   Your interpretation of the system's intended purpose and architecture based on PRIMARY CONTEXT.

   ## RIGOR & CORRECTNESS REVIEW
   Direct findings on logical, architectural, or conceptual accuracy. Ground insights in observable artifacts.

   ## FUNCTIONAL & SCALABILITY ANALYSIS
   Evidence-based discussion of strengths, bottlenecks, and limitations. Identify trade-offs.

   ## UTILITY & DESIGN INTEGRITY
   Analysis of clarity, user affordances, and maintainability. Avoid generalities.

   ## PRIORITIZED RECOMMENDATIONS
   Ordered set of targeted actions for improving rigor, performance, or clarity across layers.

   ## RAW OBSERVATIONS
   (Optional) Detailed notes, edge cases, or technical minutiae.

   **STYLE REQUIREMENTS:**
   - Write as a professional technical consultant reporting to project leadership
   - Use precise technical language, concise paragraphs, clear markdown headings
   - Ground insights in observable artifacts or metrics where possible
   - Identify and articulate trade-offs rather than simplistic judgments
   - This evaluation applies to systems ranging from simple scripts to highly complex, rigorously verified mathematical constructs—maintain analytical rigor appropriate to scope.
   ```

### Phase 3: Main Session Notification Handler
**Triggered by**: Script completion, notification file created

**Mechanism**: The slash command script prints the notification directly to stdout, which I (Claude) receive as the command result. The script itself does NOT block - it launches consultants and exits immediately.

**Claude receives message** (from command stdout):
```
🔔 External consultant(s) launched:
   - Codex (o1-preview)
   - Qwen (qwen-coder-turbo)

📂 Reports will be available at:
   ~/Projects/NINE65/v5/jobs/nine65v5/

⏱️  Receipt time: 2026-02-10 18:43:00

   Expected reports:
   - consult_codex_o1-preview_20260210_1843.md
   - consult_qwen_qwen-coder-turbo_20260210_1843.md

   (Silent wait protocol: 5 minutes, 4 checks)

Note: This is a consultation for assessment, not directive execution.
```

**Wait Protocol Implementation** (Silent):
- **Total wait time: 5 minutes** (2 + 1 + 1 + 1)
- Check schedule: 2min, 3min, 4min, 5min (4 checks total)
- **Silent operation**: I check if files exist at each interval WITHOUT announcing
- No "2 minute marker, checking for..." messages
- Only present prompt to user when:
  - Files are ready → Read and present report
  - Time expired (5 min) → Offer extend/move forward option
- User can also manually prompt me to check at any time

**After max wait time** (I use AskUserQuestion):
```
⏱️  Wait protocol time expired (checked 4 times over 5 minutes).

Reports not yet available:
- jobs/nine65v5/consult_codex_20260210_1843.md
- jobs/nine65v5/consult_qwen_20260210_1843.md

This may indicate:
- Complex analysis requiring extended time
- Consultant still processing (not necessarily failed)

Would you like to:
1. Extend wait period (reset to 5 min, continue checking)
2. Move forward (reports may still be generating, I'll note as pending)
```

This uses the AskUserQuestion tool to get explicit user direction.

### Phase 4: Report Assessment (When Ready)
**Claude's role**:
1. Read each consultant's report
2. Synthesize findings across consultants
3. Present:
   - Executive summary of key findings
   - Common themes across consultants
   - Divergent perspectives (where consultants disagree)
   - Prioritized recommendations
   - Questions for user about which directions to explore

**NOT**:
- Immediate implementation
- Directive "do this now" approach
- Treating report as the final word

## Edge Cases & Error Handling

### 1. Not in ~/Projects
```
Error: /consult must be run from within ~/Projects/<project>/
Current directory: /home/acid/Documents
```

### 2. CLI Tool Not Available
```
Error: Consultant 'codex' not found in PATH
Available: qwen, gemini, claude
Retry with: /consult --agents qwen
```

### 3. Report Generation Failure
```
⚠️  Codex report failed to generate after extended wait.
Qwen report ready: jobs/nine65v5/consult_qwen_<timestamp>.md

Continue with available reports?
```

### 4. Ambiguous Project Detection
```
Warning: Multiple projects detected in path:
- ~/Projects/NINE65 (parent)
- ~/Projects/NINE65/v5 (current)

Using: NINE65/v5
Override with: /consult --project NINE65
```

## Benefits of This Design

1. **Zero Context Bloat** - Main session never loads large files
2. **Token Efficient** - Structured wait protocol, no polling loops
3. **Multi-Perspective** - Can get 4 different consultant views
4. **Context Preservation** - Each project's unique history maintained
5. **Graceful Degradation** - Extends wait for complex tasks, doesn't assume failure
6. **Global Utility** - Works across all projects in workspace
7. **Configurable** - Default fast (Codex only), optional comprehensive (all 4)
8. **Assessment-Focused** - Reports are for consideration, not immediate action
